# cjong4-discard-risk

4人打ちリーチ麻雀のマスク済み牌配置と打牌候補から、危険度を推定する軽量なC11ライブラリです。

**5枚のRGB画像と候補の物理牌ID**を入力にするINT8推論器を実装しています。
学習器・教師データ・学習済み重みはまだありません。実際の危険度を推定するには、
学習・検証したモデルを別途用意する必要があります。テストの人工的な重みは精度を示しません。

## 設計の前提

- cjong4の136枚の物理牌を維持し、各牌の配置と履歴の結び付きを保持します。
- RGBは `discard`・`placement`・`discard_history` の3バイトそのものです。
- 正規化はプレイヤー番号の相対化だけです。牌種集約、特徴フラグへの分解、
  色補正、補間、入力値のスケーリングは行いません。
- 表ドラ表示牌の入力は一旦保留です。裏ドラも入力しません。
- 完全状態をコピーせず、`cj4m_make_player_view()` のマスク済みビューを使います。
- ルール・合法性はcjong4、危険度の推論は本ライブラリ、
  牌効率・押し引き・最終行動選択は呼び出し側が担当します。

推定目標は「今この牌を切ると、相手の少なくとも1人がロンできる可能性」です。
放銃時の失点や将来の放銃可能性は対象に含めません。

## 入力スキーマv2

入力は409バイトです。各画像を行優先・RGB交互・パディングなしで連結し、
最後の1バイトに打牌候補IDを格納します。

| 領域 | 横の牌種 × 縦の個体 | 先頭牌種ID | バイト位置 | サイズ |
| --- | --- | ---: | ---: | ---: |
| 萬子 | 9×4 | 0 | 0 | 108 |
| 筒子 | 9×4 | 9 | 108 | 108 |
| 索子 | 9×4 | 18 | 216 | 108 |
| 風牌 | 4×4 | 27 | 324 | 48 |
| 三元牌 | 3×4 | 31 | 372 | 36 |
| 打牌候補ID | 0〜135 | — | 408 | 1 |

画像内の座標 `(x, y)` に対して:

```text
tile_id = (先頭牌種ID + x) * 4 + y
offset  = 画像のバイト位置 + (y * 画像の横幅 + x) * 3

input[offset + 0] = discard           // R
input[offset + 1] = placement         // G
input[offset + 2] = discard_history   // B
input[408]       = candidate_tile_id
```

`discard` と `placement` のプレイヤービットだけを
`(元の番号 - view.player + 4) % 4` に変換し、自分を0にします。
未使用の255、捨牌順、ツモ切り、副露グループ・種類、全体の捨牌順、
リーチ宣言フラグを保持します。鳴かれた物理牌にも、
元の捨牌情報と現在の副露情報の両方が残ります。

未知の3バイトはRGB(255,255,255)、自分の通常の手牌はRGB(255,0,255)です。
色の明るさや色差そのものが危険度を意味するわけではありません。
牌の位置と他の牌の配置を含めた関係をモデルで学習します。

### v1からの変更

- `CJ4DR_INPUT_SCHEMA_VERSION` は2、ライブラリは0.2.0です。
- `cj4dr_encode_input(view, candidate, output)` からドラ引数を削除しました。
- 414バイトから409バイトへ変更し、牌ID順の三つ組を5画像の行優先順へ並べ替えました。
- **v1の末尾5バイトを削るだけでは変換できません。** マスク済みビューから再生成してください。
- 入力内にバージョン番号はありません。保存・通信時は別途記録してください。
- 旧サイズを検証・推論APIへ渡すと失敗します。

## 公開API

`include/cjong4_discard_risk/input.h`:

- `cj4dr_encode_input()`: マスク済みビューを409バイトに変換。
- `cj4dr_validate_input()`: 長さ、各フィールドの符号化、候補IDを検証。
- `cj4dr_get_image_layout()`: 画像の幅、高さ、バイト位置、先頭牌種を取得。
- `cj4dr_image_tile_id()`: 画像と座標から物理牌IDへ変換。不正なら255。
- `cj4dr_tile_rgb_offset()`: 物理牌IDからRGBのバイト位置へ変換。不正なら `SIZE_MAX`。
- `cj4dr_decode_input()`: 相対化済み配置と候補IDを損失なく復元。`wall` は255。

相手の手牌配置の混入を拒否しますが、合法性や局面全体の整合性、
情報の公開状態を完全に保証する検証ではありません。
マスク済みビューとcjong4が提示した合法打牌を使用してください。
点数、局、独立したリーチ状態などを追加する処理はありません。

各APIは失敗時に出力を変更しません。配列は宣言された容量が必要で、
入力・出力・モデル・作業領域は重複させないでください。

## 小型INT8モデルv1

```text
萬子・筒子・索子RGB → 共通の画素処理 RGB 3→4 ─┐
風牌RGB            → 風牌の画素処理 3→4 ─────┼→ 136画素×4＝544要素 ─┐
三元牌RGB          → 三元牌の画素処理 3→4 ───┘                     ├→ 中間層8 → 出力1
候補物理牌ID       → 対応する8個の重みを選択 ──────────────────────┘
```

画素処理は1×1の畳み込みに相当し、各画素のRGBに共通の重みを適用します。
風牌・三元牌にはそれぞれ別の重みを使います。個体間や画像境界をまたぐフィルターはありません。
結果は5画像・行優先・画素内チャンネル順に並べ、
位置を保持したまま全結合層へ渡します。牌間の関係はこの層で扱います。

候補IDは数値の大小として入力せず、136行×8列の重みから1行を選び、中間層の積和へ加算します。
物理牌IDのone-hot入力と同等ですが、136要素のフラグ配列は作りません。
RGB画像は3チャンネルのままです。

| 項目 | 値 |
| --- | ---: |
| INT8重み | 5,484個 / 5,484バイト |
| INT32バイアス | 21個 / 84バイト |
| シフト値 | 5個 / 5バイト |
| ファイルヘッダー | 16バイト |
| モデルファイル合計 | 5,589バイト |
| 推論用作業領域 | 552バイト |
| 入力 | 409バイト |
| 1候補の積和回数 | 5,992回 |

メモリ上のモデルにはバージョン情報と構造体のパディングもあるため、
`sizeof(cj4dr_model)` で確認できます。入力生成には409バイト、
モデル読込にはモデル1個分の一時領域も使います。
積和回数は検証・ループ・活性化・入力生成を含みません。
速度や推定精度は、このサイズだけでは保証しません。

### 整数演算

重みはINT8、積和とバイアスはINT32。RGBは0〜255の値のまま渡します。

1. 積和にバイアスを加算。中間層では候補IDの重みも加算。
2. 負値を0にする。
3. `2^shift` で割り、小数部分を切り捨てる。
4. 画素・中間層は127、出力は255を上限にする。

シフトは0〜31、バイアスは±16,777,216です。
この制約により、任意の有効なINT8重みに対するINT32積和のオーバーフローを防ぎます。
シフトと飽和はNN内部の演算で、RGBの符号化を変更する前処理ではありません。
学習・書き出し側もこの演算仕様に合わせる必要があります。

出力は `uint8_t` の危険度0〜255です。同点を許容し、0でも安全を保証しません。
百分率とは解釈せず、スコア帯と実際のロン可能率の対応は今後の学習・検証で評価します。
同一牌種の別個体の出力一致もまだ保証しません。

### 利用例

`model.h` の `cj4dr_model_decode()` で重みを読み込み、
`evaluator.h` の `cj4dr_evaluate()` で推論します。
`cj4dr_model_encode()` は明示的な直列化、
`cj4dr_model_validate()` は形式と数値範囲の検証です。
検証成功は重みが学習済みであることを示しません。既定モデルやダミー危険度は提供しません。

```c
#include "cjong4_discard_risk/evaluator.h"

/* modelは学習重み、viewはマスク済みビュー、candidateは合法打牌の物理牌ID。 */
bool score_discard(const cj4dr_model *model, const cj4_player_view *view,
                   cj4_tile_id candidate, uint8_t *danger)
{
    uint8_t input[CJ4DR_INPUT_SIZE];
    cj4dr_workspace workspace;
    if (!cj4dr_encode_input(view, candidate, input))
        return false;
    return cj4dr_evaluate(model, input, sizeof(input), &workspace, danger);
}
```

推論では動的メモリ確保、浮動小数点、libmを使用せず、入力・モデルを毎回検証します。
作業領域は繰り返し利用でき、並行実行時は分けてください。モデルと入力は変更しません。
失敗時は作業領域と危険度も変更しません。
ファイル仕様は [docs/model-format.md](docs/model-format.md) に記載しています。

## ビルドとテスト

CMake 3.16以上、C11コンパイラー、cjong4 4.0.0互換ソースまたはパッケージが必要です。

```sh
cmake -S . -B build -DCJONG4_SOURCE_DIR=../cjong4 -DCJ4DR_BUILD_TESTS=ON -DCJ4DR_BUILD_TOOLS=ON
cmake --build build -j4
ctest --test-dir build --output-on-failure
```

`CJONG4_SOURCE_DIR` を省略すると `find_package(cjong4 4.0.0 CONFIG REQUIRED)` を使用します。
既存の `cjong4::cj4` ターゲットも利用でき、依存ソースは自動取得しません。

インストールしたライブラリはC/C++から利用できます。

```sh
cmake --install build --prefix "$PWD/build/stage"
cmake -S tests/package_consumer -B build/consumer -DCMAKE_PREFIX_PATH="$PWD/build/stage"
cmake --build build/consumer -j4
ctest --test-dir build/consumer --output-on-failure
```

```cmake
find_package(cjong4_discard_risk 0.2 CONFIG REQUIRED)
target_link_libraries(your_target PRIVATE cjong4_discard_risk::cj4dr)
```

CLIはモデルと409バイトの入力ファイルを読み、危険度を1行で出力します。

```sh
./build/cj4dr_evaluate model.i8 input.rgb
```

`input.rgb` は入力全体の409バイトで、PNG/JPEGではありません。モデルは別途必要です。
サイズ不一致・不正モデル・不正入力は非ゼロ終了し、スコアを出力しません。

テストでは、全136枚の座標と損失なしの復元、座席相対化、フィールドの全256値、
候補ID保持、cjong4との接続、人工重みの既知出力、全5画像の寄与、
独立したINT64参照計算との一致、シフト・飽和・数値境界、
モデルの直列化と不正データ拒否、失敗時の出力保持を検証します。
