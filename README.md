# cjong4-discard-risk

4人打ちリーチ麻雀のマスク済み牌配置から、**全34牌種の危険度を一括推定する**
軽量なC11ライブラリです。

入力は5枚のRGB画像、出力は34×1の8ビットグレースケールです。
候補牌IDは入力せず、手牌にない牌種も含めて全34種を出力します。
実際に切れる牌か、どの牌を選ぶかは呼び出し側が判断します。

INT8推論器とLinux向けの学習・モデル書き出しツールを実装しています。
学習手順は [training/README.md](training/README.md) を参照してください。
合法局面の教師データ生成器・学習済み重みはまだありません。
実際の危険度を推定するには、学習・検証したモデルが必要です。
テストの人工的な重みは、推論の動作確認用です。

## 設計の前提

- cjong4の136枚の物理牌を維持し、各牌の配置と履歴の結び付きを保持します。
- RGBは各物理牌の `discard`・`placement`・`discard_history` の3バイトです。
- 正規化はプレイヤー番号の相対化のみです。入力の牌種集約、特徴フラグへの分解、
  色補正、補間、入力値のスケーリングは行いません。
- 表ドラ表示牌は一旦保留です。裏ドラも入力しません。
- `cj4m_make_player_view()` のマスク済みビューを使います。
- ルール・合法性はcjong4、危険度推定は本ライブラリ、
  合法打牌の選別・牌効率・押し引き・最終行動選択は呼び出し側が担当します。

推定目標は、牌種ごとの「仮に今この牌種を切ると、相手の少なくとも1人がロンできる可能性」です。
放銃時の失点や将来の放銃可能性は対象に含めません。

## 入力スキーマv3

入力は408バイトです。画像を行優先・RGB交互・パディングなしで連結します。

| 領域 | 横の牌種 × 縦の個体 | 先頭牌種ID | バイト位置 | サイズ |
| --- | --- | ---: | ---: | ---: |
| 萬子 | 9×4 | 0 | 0 | 108 |
| 筒子 | 9×4 | 9 | 108 | 108 |
| 索子 | 9×4 | 18 | 216 | 108 |
| 風牌 | 4×4 | 27 | 324 | 48 |
| 三元牌 | 3×4 | 31 | 372 | 36 |

画像内の座標 `(x, y)` に対して:

```text
tile_id = (先頭牌種ID + x) * 4 + y
offset  = 画像のバイト位置 + (y * 画像の横幅 + x) * 3

input[offset + 0] = discard           // R
input[offset + 1] = placement         // G
input[offset + 2] = discard_history   // B
```

`discard` と `placement` のプレイヤービットだけを
`(元の番号 - view.player + 4) % 4` に変換し、自分を0にします。
未使用の255、捨牌順、ツモ切り、副露グループ・種類、全体の捨牌順、
リーチ宣言フラグを保持します。鳴かれた物理牌にも、
元の捨牌情報と現在の副露情報の両方が残ります。

未知の3バイトはRGB(255,255,255)、自分の通常の手牌はRGB(255,0,255)です。
色の明るさや色差そのものが危険度を意味するわけではありません。
牌の位置と他の牌の配置を含めた関係をモデルで学習します。

### 以前の形式からの変更

ライブラリは0.3.0、入力スキーマはv3、モデル形式はv2です。

- `cj4dr_encode_input(view, output)` から候補IDの引数を削除しました。
- `cj4dr_decode_input(input, size, locations)` は配置だけを復元します。
- v2の5画像のバイト配置は維持し、末尾の候補IDを削除しました。
  v2であることを確認したデータに限り、先頭408バイトをv3画像として移行できます。
- v1は牌ID順・ドラありの414バイトです。単純な切り詰めでは移行できません。
- 入力にバージョン番号は含めません。保存・通信時は別途記録してください。
- 検証・推論APIは旧409/414バイト入力を拒否します。
- 候補ID用の学習重みを廃止し、出力を1個から34個へ変更しました。
  旧モデルファイルは読み込めず、新しい構成での学習が必要です。

## 出力：34×1グレースケール

出力は `uint8_t danger[34]`、1画素1バイトです。
画素の横位置はcjong4の牌種IDそのものです。

| 画素位置（牌種ID） | 牌種 |
| --- | --- |
| 0〜8 | 一萬〜九萬 |
| 9〜17 | 一筒〜九筒 |
| 18〜26 | 一索〜九索 |
| 27〜30 | 東・南・西・北 |
| 31〜33 | 白・發・中 |

`00` は最低危険度（黒）、`FF` は最高危険度（白）。
各画素は独立したスコアで、全体の合計を一定にする正規化は行いません。
未所持・打牌不能な牌種も通常のスコアを出力し、特別な無効値には置き換えません。

入力の同一牌種4枚は個別に保持します。出力は牌種ごとに1値なので、
同じ牌種のどの物理牌を候補に選んでも同じ画素を参照します。
これは、入力内の物理牌IDの入れ替えに対するモデルの不変性まで保証するものではありません。

スコアは百分率ではなく、0も安全の保証ではありません。
局面をまたいだスコア帯と実際のロン可能率の対応は、学習後に検証します。

## 学習データの方針

ランダム生成した局面に、ルール上の意味を指定して個別作成した局面を組み合わせます。
ランダム局面は状態遷移や整合性検証を通し、RGBの各バイトを無関係に乱数化したものを
麻雀の教師データにはしません。完全状態を教師判定に使用する場合も、
NNに渡す画像は必ずマスク済みビューから生成します。

個別データは自明な安全条件などを教えるために用います。
例として、他家3人が同じ牌種をそれぞれ捨てている場合、その牌種の教師値を `00` にできます。
また「自身の現物」「リーチ成立後に通った牌」などの根拠を他家ごとに組み合わせ、
全員に対する安全条件が成立した牌種に `00` を付けられます。

直前の通過牌を扱う場合は、手番・リーチ成立時点・間に入る鳴きやツモ・役の条件を明示し、
cjong4の判定と整合する局面を作ります。
条件を維持して対象牌種、物理牌の個体、捨牌順、周囲の配置を変えることで、
特定の1枚の画像だけに依存しないデータを増やします。

### 部分的な教師指定

1サンプルの論理的な構成は次のとおりです。
JSONLからNPZへ保存するツールと、指定マスクに対応する学習器を用意しています。
保存形式・作成例は [training/README.md](training/README.md) を参照してください。

| 項目 | 内容 |
| --- | --- |
| 入力 | 5枚のRGB画像、408バイト |
| 教師値 | `target[34]`、各牌種の00〜FF |
| 指定マスク | `mask[34]`、1=教師値あり、0=未指定 |
| 管理情報 | 生成元・対局ID・安全条件など。NNには入力しない |

例えば五萬だけを安全と指定する場合は、`target[4] = 0x00`、
`mask[4] = 1`、それ以外のマスクは0にします。
未指定の教師値の格納値は学習に使わず、未指定を安全牌として学習させません。
指定された出力だけに損失を適用し、指定がないサンプルは学習対象から除外します。
マスクは学習専用で、推論入力には加えません。

**00は教師値です。推論時に必ず00を返す要求ではありません。**
安全ルールによる出力の上書きは行わず、モデルの推定値を返します。

安全例と通常・危険局面を組み合わせ、データの比率によるスコアの偏りを検証します。
学習・検証・最終評価は対局や派生ケースの元データ単位で分離し、
同じケースから派生した近似局面が評価側に混ざらないようにします。
損失は指定要素のグレースケールMSEで、Cと同じ整数演算をforwardで再現する
量子化学習を実装しています。ランダム局面の教師生成手順と尺度補正は今後決定します。

## 小型INT8モデルv2

```text
萬子・筒子・索子RGB → 共通の画素処理 RGB 3→4 ─┐
風牌RGB            → 風牌の画素処理 3→4 ─────┼→ 136画素×4＝544要素 → 中間層8 → 出力34
三元牌RGB          → 三元牌の画素処理 3→4 ───┘
```

画素処理は1×1の畳み込みに相当します。数牌3色で共通の重みを使い、
風牌・三元牌にはそれぞれ別の重みを使います。
画像境界や縦の個体間をまたぐフィルターはありません。
結果は5画像・行優先・画素内チャンネル順に並べ、
位置を保持したまま全結合層へ渡します。

画像処理と中間層を1回計算し、その結果から34個のスコアを出します。
出力ごとに8個の重みと1個のバイアスを持ち、出力シフトは34種で共有します。

| 項目 | 値 |
| --- | ---: |
| INT8重み | 4,660個 / 4,660バイト |
| INT32バイアス | 54個 / 216バイト |
| シフト値 | 5個 / 5バイト |
| ファイルヘッダー | 16バイト |
| モデルファイル合計 | 4,897バイト |
| 推論用作業領域 | 552バイト |
| 入力 / 出力 | 408バイト / 34バイト |
| 全34種を一括評価する積和回数 | 6,256回 |

メモリ上のモデルはバージョン情報とパディングも含むため、
`sizeof(cj4dr_model)` で確認できます。入力生成には408バイト、
モデル読込にはモデル1個分の一時領域も使います。
積和回数は検証・ループ・活性化・入力生成を含みません。
中間層8ノードで十分な精度が出るかは未検証です。

### 整数演算

重みはINT8、積和とバイアスはINT32。RGBは0〜255の値のまま渡します。

1. 積和にバイアスを加算。
2. 負値を0にする。
3. `2^shift` で割り、小数部分を切り捨てる。
4. 画素・中間層は127、各出力は255を上限にする。

シフトは0〜31、バイアスは±16,777,216です。
この制約により、有効な重みに対するINT32積和のオーバーフローを防ぎます。
シフトと飽和はNN内部の演算で、RGBの前処理ではありません。
学習・書き出し側もこの演算仕様に合わせる必要があります。

## 公開APIと利用例

`input.h` は入力生成・検証・座標変換・損失なしの配置復元、
`model.h` はモデルの検証・直列化・読込、
`evaluator.h` は34牌種一括推論を提供します。
`cj4dr_model_decode()` で学習済み重みを読み込んでから使用します。

```c
#include "cjong4_discard_risk/evaluator.h"

bool score_position(const cj4dr_model *model, const cj4_player_view *view,
                    uint8_t danger[CJ4DR_OUTPUT_SIZE])
{
    uint8_t input[CJ4DR_INPUT_SIZE];
    cj4dr_workspace workspace;
    if (!cj4dr_encode_input(view, input))
        return false;
    return cj4dr_evaluate(model, input, sizeof(input), &workspace, danger);
}

/* 呼び出し側が合法手一覧から選んだ物理牌ID tile の値は、
 * danger[cj4_tile_get_type(tile)] で参照する。 */
```

推論は動的メモリ確保・浮動小数点・libmを使用せず、毎回入力とモデルを検証します。
モデルと入力は変更しません。失敗時は作業領域と34個すべての出力を変更しません。
出力配列は34バイト必要です。入力・出力・モデル・作業領域は重複させず、
並行実行時は作業領域を分けてください。

入力検証は相手の手牌配置の混入を拒否しますが、局面全体の整合性や合法性を保証しません。
`cj4dr_decode_input(input, size, locations)` は相対化済み配置を復元し、`wall` は255に設定します。
モデルの検証成功は、重みが学習済みであることを示しません。
ファイル仕様は [docs/model-format.md](docs/model-format.md) を参照してください。

## ビルドとテスト

CMake 3.16以上、C11コンパイラー、cjong4 4.0.0互換ソースまたはパッケージが必要です。

```sh
cmake -S . -B build -DCJONG4_SOURCE_DIR=../cjong4 -DCJ4DR_BUILD_TESTS=ON -DCJ4DR_BUILD_TOOLS=ON
cmake --build build -j4
ctest --test-dir build --output-on-failure
```

`CJONG4_SOURCE_DIR` を省略すると `find_package(cjong4 4.0.0 CONFIG REQUIRED)` を使用します。
既存の `cjong4::cj4` ターゲットも利用でき、依存ソースは自動取得しません。

```sh
cmake --install build --prefix "$PWD/build/stage"
cmake -S tests/package_consumer -B build/consumer -DCMAKE_PREFIX_PATH="$PWD/build/stage"
cmake --build build/consumer -j4
ctest --test-dir build/consumer --output-on-failure
```

```cmake
find_package(cjong4_discard_risk 0.3 CONFIG REQUIRED)
target_link_libraries(your_target PRIVATE cjong4_discard_risk::cj4dr)
```

CLIはモデルと408バイトの入力を読み、牌種ID順に34個の2桁16進数を1行で出力します。
`--pgm` を付けると34×1のPGM画像（P2形式、最大値255）を標準出力に書き出します。

```sh
./build/cj4dr_evaluate model.i8 input.rgb
./build/cj4dr_evaluate --pgm model.i8 input.rgb > danger.pgm
```

`input.rgb` は5画像を連結した生の408バイトで、PNG/JPEGではありません。
サイズ不一致・不正モデル・不正入力は非ゼロ終了し、スコアや画像を出力しません。

テストは全136枚の座標・復元、座席相対化、フィールドの全256値、cjong4との接続、
全34出力の順序・独立した重み・飽和、未所持牌種の出力、全5画像の寄与、
INT64参照計算との一致、モデル直列化、不正・旧形式の拒否、失敗時の出力保持を確認します。
テストとCLIを有効にし、Python 3が見つかる場合はCLIの16進数・PGM出力テストも実行します。
