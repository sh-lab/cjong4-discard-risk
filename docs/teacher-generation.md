# 教師データ生成 v1

`cj4dr_generate` はcjong4の状態遷移とロン判定を使って、
既存の `training.data pack` が読めるJSONLを生成します。
`CJ4DR_BUILD_TOOLS=ON` でビルドします。C推論ライブラリのAPI・モデル形式は変更しません。

## 教師値と入力

各打牌判断の**直前**に、手番プレイヤーのマスク済みビューを
`cj4m_make_player_view()` → `cj4dr_encode_input()` で408バイトにします。
他家の手牌や山順をNN入力へ渡しません。入力の正規化は従来のプレイヤー相対化だけです。

ランダム局面では、`cj4_can_discard()` が許可する物理牌について次を行います。

1. 完全状態のコピー上で `cj4_do_discard()` を実行。
2. 他家3人に `cj4_can_ron()` を適用。
3. 1人でもロン可能なら牌種の教師値FF、全員ロン不可なら00、マスク1。

役・恒久フリテン・同巡フリテン・リーチ後の見逃しはcjong4の判定に従います。
教師は「ロンできる人が存在するか」であり、実際にロンを選ぶか、最終失点がいくらか、
将来の打牌が安全かの判定ではありません。推論時に安全ルールを適用する処理も加えません。

同一牌種の複数の合法な物理牌は1つの教師にまとめ、判定の不一致があれば生成を中止します。
未所持・打牌不能な牌種はマスク0のままです。リーチ後は合法なツモ切りの牌種だけを指定します。
リーチ宣言・加槓・暗槓の選択リスクは教師にせず、通常の打牌を評価します。
NNの出力は従来通り34種すべてです。

00/FFは、その完全局面の結果を示す教師値です。
マスク済み入力だけでは区別できない完全局面があるため、同じRGBに異なる教師が付く場合もあります。
その分布を学習するものであり、1件の教師が観測情報からの確定的な安全判定を意味するわけではありません。

## ランダム局面

```sh
mkdir -p datasets
./build/cj4dr_generate --mode random \
  --rounds 100 --seed 60000 --epsilon-percent 20 \
  --output datasets/random-60000.jsonl
```

シャッフルした136枚の牌山で、独立した局を開始します。
各局は既定ルールの東1局・親0・初期点数で始め、局終了までcjong4の合法操作で進めます。
`--rounds` は局数であり、半荘数ではありません。各打牌判断につき1行を記録します。

行動方針は和了可能なら和了し、その他は次のように選びます。

- `--epsilon-percent` の割合で合法手一覧から一様に選択。
- 残りはリーチがあれば選択し、打牌はシャンテン数最小の候補からランダムに選択。
- 打牌・リーチがなければパスを優先。

既定の探索率は20%です。100にすると、和了優先以外は一様なランダム選択になります。
シャンテン計算も手番プレイヤーのマスク済みビューだけを参照します。
これは教師データの局面生成方針で、NNのRGB入力をシャンテンなどに置き換えるものではありません。

`--max-steps` の既定は1局1,024ステップです。
状態が進まない、APIが失敗する、上限を超える場合はseed・局番号・状態を出して失敗します。
失敗した局を黙ってスキップしたり、未指定を00にしたりしません。

## 個別ケース

```sh
./build/cj4dr_generate --mode cases --variants 10 --seed 70000 \
  --output datasets/manual-70000.jsonl
```

34牌種 × 3条件 × variants件を生成します（上記は1,020件）。
各行は対象牌種だけマスク1とし、他の33種は未指定です。

| source | 条件 | 教師値 |
| --- | --- | --- |
| `all-genbutsu` | 他家3人が対象牌種を1枚ずつ捨て、自分が4枚目を所持 | 00 |
| `riichi-passed` | 下家が対象牌の七対子単騎でリーチ。対面と上家が順に対象牌を切り、下家が見逃した直後の自分の手番 | 00 |
| `riichi-danger` | 下家が対象牌の七対子単騎でリーチ。対象牌がまだ通っておらず、自分が切ればロン可能 | FF |

どのケースも、合法な136枚の牌山・配牌を組んでから実際の打牌・リーチ・パスを再生します。
RGBのビットだけを変更して「合法局面」とすることはありません。
周囲の牌配置と物理牌の個体をseedで変え、最後にcjong4の教師判定でも期待値を検証します。

リーチ後通過ケースでは下家がロン可能な牌を実際に見逃すので、リーチフリテンが成立します。
対面・上家にも同じ牌が現物となり、全他家について00です。
「1人に対して通ったから全員に安全」とは扱いません。
これは個別条件の初期セットであり、安全条件の網羅や一般局面からの全条件抽出ではありません。

## 分割・再現性・出力

ランダム局面のgroupはseed＋局番号です。同じ局の全手番・全観測者を同じgroupにします。
個別ケースは対象牌種単位でgroupを固定し、seed・variant・3条件を跨いでまとめます。
派生ケースが学習側と評価側へ分かれることを防ぐためです。

各行には、入力スキーマ、生成器バージョン、既定ルール、seed、局番号またはvariant、
ステップ、観測者、条件名、対象牌種等の管理情報を記録します。NNへの入力には使いません。
再現性は同じ生成器・cjong4の実装・引数で確認してください。

`--start-round` でランダム生成を分割できます。
同じseedの重ならない局番号範囲を指定すれば、まとめて生成した場合と同じ行になります。

```sh
./build/cj4dr_generate --rounds 50 --start-round 0 --seed 60000 \
  --output datasets/random-60000-part0.jsonl
./build/cj4dr_generate --rounds 50 --start-round 50 --seed 60000 \
  --output datasets/random-60000-part1.jsonl
```

出力は一旦 `指定パス.partial` へ書き、全件成功後に指定パスへ移します。
既存の出力・partialは上書きしません。通常の失敗・SIGINT・SIGTERMではpartialを削除します。
強制終了や電源断で残ったpartialは未完成データです。
進捗と指定教師値の00/FF件数は標準エラーへ出します。

## 学習へ渡す

JSONLはRGBを16進数で内包するため、出力ファイルを結合しても画像パスの調整は不要です。

```sh
cat datasets/random-60000.jsonl datasets/manual-70000.jsonl > datasets/all.jsonl
python -m training.data pack datasets/all.jsonl datasets/all.npz
python -m training.data split datasets/all.npz datasets/split --seed 1
python -m training.train \
  --train datasets/split/train.npz --validation datasets/split/validation.npz \
  --output runs/risk-001 --epochs 100 --batch-size 256 --device cpu
```

同じ元データの再生成分を重複投入しないでください。まず小規模生成で件数・00/FF比率を確認します。
ランダム局面は00が多く、手作りケースを増やせばその条件の比率が上がります。
いずれも実戦の分布そのものではないため、生成件数や学習損失だけで実用精度を判断しません。
実戦評価・過小推定・条件ごとの評価と尺度補正は別途必要です。
学習・再開・INT8書き出しの詳細は [学習手順](../training/README.md) を参照してください。
